# 智档本地调试部署文档

## 1. 文档目的

本文档用于指导你在**本地开发环境**中启动和调试 `智档` 项目，包括：

- 后端启动
- 前端启动
- 数据库准备
- 环境变量配置
- 常见问题排查
- 健康检查与验证

---

## 2. 项目结构

当前项目结构如下：

- `backend/`：FastAPI 后端
- `frontend/`：Vue 3 + Vite 前端
- `migrations/`：数据库迁移文件
- `scripts/`：初始化脚本
- `.env.example`：环境变量示例文件

---

## 3. 本地运行环境要求

### 3.1 基础环境

建议安装以下工具：

- Python 3.10+  
- Node.js 18+  
- npm 或 pnpm  
- PostgreSQL 14+  
- Git  
- 终端工具（PowerShell、CMD、Windows Terminal 均可）

### 3.2 推荐开发工具

- VS Code / Cursor
- PostgreSQL 客户端工具（如 DBeaver、Navicat）
- API 调试工具（Postman、Apifox、curl）

---

## 4. 环境变量配置

本项目运行前需要配置环境变量。

### 4.1 创建环境变量文件

在项目根目录复制示例文件：

```bash
cp .env.example .env
```

如果是在 Windows PowerShell 下：

```powershell
Copy-Item .env.example .env
```

### 4.2 必填配置项

根据当前项目说明，至少需要配置以下变量：

- `DATABASE_URL`
- `JWT_SECRET`
- `LOG_LEVEL`
- `ENVIRONMENT`

### 4.3 配置示例

```env
DATABASE_URL=postgresql://username:password@localhost:5432/zhidang
JWT_SECRET=replace_with_a_strong_secret
LOG_LEVEL=INFO
ENVIRONMENT=development
```

### 4.4 配置说明

#### `DATABASE_URL`
数据库连接地址，格式通常为：

```text
postgresql://用户名:密码@主机:端口/数据库名
```

例如：

```text
postgresql://postgres:123456@localhost:5432/zhidang
```

#### `JWT_SECRET`
用于签发和校验登录令牌，建议使用足够复杂的随机字符串。

#### `LOG_LEVEL`
日志级别，开发环境建议设置为：

```text
DEBUG
```

#### `ENVIRONMENT`
环境标识，开发时建议：

```text
development
```

## 5. 数据库准备

项目使用 PostgreSQL，并通过 Alembic 管理数据库迁移。

### 5.1 启动 PostgreSQL

如果你本机已经安装 PostgreSQL，确认数据库服务已启动。

如果尚未创建数据库，建议先创建：

- 数据库名：`zhidang`
- 用户名：`postgres` 或你自己的账号
- 密码：按你的本地配置填写

### 5.2 创建数据库

在 PostgreSQL 中创建数据库，例如：

```sql
CREATE DATABASE zhidang;
```

如果你使用图形化工具，也可以直接通过工具创建。

### 5.3 执行数据库迁移

如果项目已配置 Alembic，可在项目根目录执行：

```bash
alembic upgrade head
```

如果迁移命令需要在后端目录执行，请根据实际结构进入对应目录后再运行。

## 6. 后端本地启动

后端是 FastAPI 应用。

### 6.1 安装 Python 依赖

在项目根目录或后端目录中执行，视 `requirements.txt` 所在位置而定。

如果根目录有依赖文件：

```bash
pip install -r requirements.txt
```

如果后端目录内有依赖文件，则进入后端目录：

```bash
cd backend
pip install -r requirements.txt
```

### 6.2 启动后端服务

开发模式推荐使用热重载：

```bash
uvicorn backend.app.main:app --reload --host 0.0.0.0 --port 8000
```

如果你的入口文件不在这个路径，请以实际项目为准调整。

### 6.3 后端访问地址

默认启动后，后端通常可访问：

```text
http://localhost:8000
```

健康检查接口通常包括：

- `/health`
- `/api/v1/health`

例如：

```text
http://localhost:8000/health
```

## 7. 前端本地启动

前端是 Vue 3 + Vite 项目。

### 7.1 安装前端依赖

进入前端目录：

```bash
cd frontend
npm install
```

如果你使用 pnpm：

```bash
pnpm install
```

### 7.2 启动开发服务

```bash
npm run dev
```

或者：

```bash
pnpm dev
```

### 7.3 默认访问地址

Vite 启动后通常访问：

```text
http://localhost:5173
```

如果端口被占用，Vite 会自动切换到其他端口，请看终端输出。

## 8. 本地调试流程

下面是一套推荐的本地调试顺序。

### 8.1 第一步：确认数据库可用

确认 PostgreSQL 已启动，数据库 `zhidang` 已创建，连接字符串正确。

### 8.2 第二步：配置 `.env`

检查以下变量：

- `DATABASE_URL`
- `JWT_SECRET`
- `LOG_LEVEL`
- `ENVIRONMENT`

### 8.3 第三步：启动后端

运行后端服务后，观察终端是否有报错。

### 8.4 第四步：启动前端

前端启动成功后，访问页面，确认是否能正常加载。

### 8.5 第五步：验证接口

访问健康检查接口：

```bash
curl http://localhost:8000/health
```

或者：

```bash
curl http://localhost:8000/api/v1/health
```

### 8.6 第六步：验证页面

项目主要页面包括：

- `/review`
- `/config`
- `/llm`

你可以逐个打开，检查页面是否能正常渲染与交互。

## 9. 推荐的本地调试方式

### 9.1 前后端分开启动

这是最推荐的本地调试方式：

- 后端单独运行：便于看接口报错和日志
- 前端单独运行：便于看页面渲染与请求问题

### 9.2 数据库单独运行

保持 PostgreSQL 常驻，方便做迁移和数据检查。

### 9.3 调试时开启详细日志

建议后端日志级别设为：

```env
LOG_LEVEL=DEBUG
```

这样更容易定位问题。

## 10. 常见问题排查

### 10.1 后端启动失败

#### 可能原因
- Python 依赖未安装
- `DATABASE_URL` 配置错误
- 数据库未启动
- 端口 8000 被占用
- 入口路径写错

#### 排查方法
1. 检查依赖安装：
   ```bash
   pip install -r requirements.txt
   ```
2. 检查数据库是否可连接
3. 检查 `.env` 配置
4. 查看终端报错信息
5. 更换启动端口：
   ```bash
   uvicorn backend.app.main:app --reload --host 0.0.0.0 --port 8001
   ```

---
